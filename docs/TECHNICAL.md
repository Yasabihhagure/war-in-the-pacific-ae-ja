# 技術資料

差し替え `ddraw.dll` の仕組みと、ゲーム本体の解析で分かったことのまとめです。ソースは `src/ddraw/`。

対象: `War in the Pacific Admiral Edition.exe`（2016-07-10、5,054,464 バイト、ゲーム内の表記は 1.8.11.26a）。32 ビット（i386）、イメージベース 0x400000、ASLR なし。以下のアドレスはこの exe のものです。

## 1. 全体の構成

| ファイル | 役目 |
| --- | --- |
| `ddraw_proxy.cpp` | 本物の `ddraw.dll`（System32 / SysWOW64）への転送、設定と訳文の読み込み、IAT のフック（`CreateFileA` など）、ログ |
| `game_hooks.cpp` | ゲーム内部の関数の差し替え（文字の描画、幅、折り返し、書式の組み立て）、名前のつなぎ方、シナリオ説明の改行し直し |
| `display.cpp` | ウィンドウモードの拡大（窓の大きさ、マウス座標、画面の転送の横取り） |
| `scaler.cpp` | ゲーム画面の写し（キャンバス）と、自前のバイリニア補間による拡大 |

ゲームの関数の差し替えは、メモリ上で関数の先頭を `jmp` に書き換えて行います（exe のファイルは書き換えない）。書き換える前に先頭の機械語を確かめ、合わなければその関数は差し替えません（ログに `bytes mismatch` と出る）。

## 2. 文字の描き方

- ゲームは `TextOutA` で文章を描いていない。起動時に、フォント4種類それぞれで 0x01〜0x7F の文字を1文字ずつ描いて文字画像の表を作り（`0x7f8c80`）、文章はそこから自前で貼り付ける。0x80 以上のバイトは読み飛ばすので、そのままでは日本語が出ない。
- フォントの管理用データ: `+0` 文字数（128）、`+4` 等幅時の幅、`+8` 高さ、`+0x10`〜`+0x1c` 色4つ、`+0x820 + 56*c` 文字 c の画像、`+0x824 + 56*c` 文字 c の送り幅。`[0xfe8aeea]` ≠ 0 なら等幅。
- 色は COLORREF と同じ `0x00BBGGRR`。文字画像は白で作られ、`0x7f6cd0` が `+0x10`（番号0。文字の色）などの色に塗り替える。色の設定は `0x7f3e60(font, 番号, 色)`。
- 現在のフォント `[0xfe73458]`。太字のフォントは `0x7adeb58`、`0x4270ae8`。

差し替える関数:

| アドレス | 中身 | 差し替えの内容 |
| --- | --- | --- |
| `0x7fa920(x, y, str, target, clip)` | 1行を描く最下層 | 英数字の部分は元の関数、Shift_JIS の部分は描画先サーフェスの DC に GDI（日本語フォント）で描く。`clip` は切り抜く範囲（RECT*。空で描く先が画面なら `0xfe732ac` の範囲） |
| `0x7f43e0(str, font)` | 文字列の幅 | 日本語の部分は GDI で測って足す |
| `0x7ed780(str, 行頭*, 長さ*, 最大行数, 長さ, 最大幅, 区切り)` | 折り返し | 日本語を含むときは自前で折り返す（日本語の文字の間でも折り返し、句読点・閉じ括弧を行頭に、開き括弧を行末に置かない）。`\n` は印を立てるだけ、印のあとの `\r` と `~` で改行 |

## 3. 訳文への置き換え

### 3.1 書式の差し替え

ゲームの文は、書式（`%s が %s に到着` など）を組み立ててから描かれる。書式を受け取る関数の入口で、スタック上の書式の引数を訳文の書式に差し替えてから、元の関数へ飛ぶ。

| アドレス | 関数 | 主な呼び出し元 |
| --- | --- | --- |
| `0x7f13c0(size, buf, fmt, va)` | ゲーム側の書式組み立ての共通の入口 | 画面の文言、ツールチップ（`0x40d180`） |
| `0x80f1ab(buf, fmt, ...)` | C 標準ライブラリの sprintf | 1,479 か所 |
| `0x8111b0(buf, fmt, va)` | C 標準ライブラリの vsprintf | 戦闘報告の行（`0x505290`。行の表は `0x73f649c` から 101 バイトずつ） |

あわせて、書式の `%s` に入る文字列（文の断片や名前）も訳文の表で引き、訳があれば訳文を指すポインタに差し替える。`%.20s` のような上限があるときは、2バイト文字を途中で切らない長さに収めた訳文を渡す。ファイル名を組み立てる書式（`\` や `.bmp` などを含む）では差し替えない。

### 3.2 訳文の引き方

- 訳文の表のキーは、英文のバイト列の FNV-1a 64bit（`h:` + 16桁の16進）。原作の英文を配布物に含めないため。
- 文の末尾の `%番号@`（ツールチップなどの番号）は、外して引き、訳に付け直す。
- 画面の文言（`ja.tsv`）が名前の表（`names\*.tsv`）より優先。

### 3.3 名前の種類の見分け

同じ綴りの名前が艦と地名にある（Sendai → 川内／仙台 など）。DLL は、`%s` に渡された文字列のアドレスが、ゲーム中の配列のどこにあるかで種類を決め、その種類の表を先に引く。

| 配列 | 先頭 | 大きさ | 先に引く表 |
| --- | --- | --- | --- |
| 艦船 | `0x1dad540` | `0x8d9a00` | ships → ship_classes |
| 艦型 | `0x3aee328` | `0x1cfde0` | ship_classes → ships |

範囲の外の文字列は、共通の表で引く。シナリオのデータは `0x54b790(path, 読み込み先)` でも読み込まれる（wps → `0x3cbe1a8`、wpc → `0x756c4a8`、wpl → `0x3159a88`）。調べるときは ini の `[Debug] LogNameAddr=1` で、名前の文字列のアドレスがログに出る（`[addr]`）。

### 3.4 地上部隊の名前のつなぎ方

地上部隊の名前は「名前の部分」と「種類」を書式 `%s %s` で組み立てる（例 `Kure 3rd` + `SNLF`）。種類は exe の表（略記 40 と正式 45。`translation/unit_types.tsv` にハッシュで持つ）。`%s %s` の後ろが種類で、名前と種類がどちらも日本語のときは、

- 間の空白を詰める（呉第3 陸戦隊 → 呉第3陸戦隊）
- 名前の訳がすでに種類を含んでいれば（隊・団・部・群で終わる、種類の訳で終わる、海・陸・空以外の「軍」で終わる）、種類を付けない

### 3.5 シナリオの説明文

`CreateFileA`（IAT）で `SCEN\*.txt` を開くときに、`witpae_ja\SCEN\` の同名のファイルに差し替える。ゲームの読み込み（`0x61ef00` 付近）は `fgets` で最大 80 バイトずつ読み、幅 280px を超える行は最後の空白で切り詰め、空白がなければ行を捨てる。そのため DLL が、今の日本語の文字の大きさで幅 `ScenWidth`（既定 270px）・78 バイト以内に改行し直したものを `witpae_ja\cache\` に書いて開かせる。

## 4. ウィンドウモードの拡大

- 窓の作成（`CreateWindowExA`、`0x7fe7cd`）で大きさを変え、ゲームの WndProc（`0x7fdcf0`）の前後に自前の処理を挟む（`WM_GETMINMAXINFO` の固定を外す、マウス座標を倍率で割る）。
- ゲームの解像度は `[0x886a58]`（幅）、`[0x886a5c]`（高さ）。起動直後 800×600、メインメニューで 1024×768。
- 主サーフェスへの転送（`IDirectDrawSurface7::Blt`）を横取りし、DLL が持つゲーム画面の写し（キャンバス）に反映して、転送された部分だけを拡大して窓へ描く。
- ゲームはツールチップなどを消すとき、主サーフェスから背景を読み戻す（`0x7fac10` → `0x7f7de0` → `0x7f5bc0`）。拡大中は本物の主サーフェスに正しい絵がないので、主サーフェスからの転送はキャンバスから書き込む。

## 5. シナリオのデータの名前

名前はシナリオのデータ `SCEN\wp?NNN.dat` に、20 バイトの欄（19 文字 + 終端）で並んでいる。

| ファイル | 中身 | 対訳表 |
| --- | --- | --- |
| wps | 艦船 | ships |
| wpc | 艦型 | ship_classes |
| wpa | 航空機 | aircraft |
| wpg | 航空隊 | air_groups |
| wpl | 拠点（地名）と地上部隊・司令部 | places、ground_units |
| wph | 指揮官 | leaders |
| wpp | パイロット | pilots |
| wpd | 兵器（訳していない） | |

訳は CP932 で 19 バイト以内にする（`%.20s` などで切られるため）。データの名前には末尾に空白の付いたもの（`Aoba-1 ` など）があり、ゲームはそのまま描くので、DLL は空白つきの形で引く。空白を落として引く道具のために、空白なしの形のキーにも同じ訳を入れてある（`tools/names.py aliases`、メモ「別名: 末尾の空白なし」）。人物の名前は「姓, 頭文字」の形で、姓ごとの訳（`translation/surnames.tsv`）から「姓の訳 + 頭文字」を組み立てる（`tools/names.py persons`）。
